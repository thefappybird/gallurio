Stronger than the other four areas — deliberate accessibility engineering is visible in several places, not incidental.

## What's working
- **Forms** — fully labeled. Contact form (`app/(public)/w/[orgSlug]/_components/ContactForm.tsx:448,454,460,477,499,545,561,565,605,627,663`) pairs every input with `<label htmlFor>`, plus `aria-label` on the icon-only remove-session button (:529). Booking wizard payments step same pattern (`booking-wizard-steps/payments-step.tsx:91,109,119,144`).
- **Dialogs/modals** — `components/ui/dialog.tsx:4,10` wraps `@base-ui/react/dialog`, which natively traps focus, returns focus on close, and closes on Escape. `booking-detail-modal.tsx` uses this primitive rather than a custom implementation.
- **Drag-and-drop keyboard alternative** — Puck editor block reordering has a non-drag path: `BlockActionsToolbar.tsx:251-273` provides Move Up/Move Down/Duplicate buttons with `aria-label` (:167,237) alongside drag, correctly satisfying CLAUDE.md's "drag needs visible affordances" rule.
- **Calendar keyboard operability** — `booking-calendar.tsx:1130` uses react-big-calendar's `selectable` + `onSelectEvent`/`onSelectSlot`, so event selection isn't drag-only.
- **Color never sole signal** — `booking-detail-modal.tsx:1793-1806` marks the colored status dot `aria-hidden` (:1801) and always pairs it with visible text (`<span>{statusLabel}</span>`, :1805) plus a wrapper `aria-label`. Calendar status chips (`booking-calendar.tsx:393,462`) build `aria-label` from title + status text, not color alone.
- **Image alt text** — decorative images correctly use `alt=""` (`ContainerBackgroundSlideshow.tsx:86,130`, `bannerLayers.tsx:66`, `manualBlocks.tsx:991,1373`, `ImmersiveViewer.tsx:234`); content images (gallery blocks) use meaningful, localized fallback text via `galleryAltFallback(...)` (`GalleryGridBlock.tsx:100-101,228`, `GalleryMasonryBlock.tsx:132,265`).
- **Custom widget ARIA** — `components/ui/color-picker.tsx:120-172` has `role="group"`, `aria-pressed`, `aria-hidden` on the decorative swatch. `lib/page-builder/galleryPicker/MediaPicker.tsx:636-1108` implements a real listbox/option/checkbox ARIA pattern (`role="listbox"`, `role="option"`, `role="checkbox"` with `aria-checked`/`aria-selected`, `role="alert"` for errors) — a code comment at :1032-1035 explains a deliberate choice about where `role="option"` sits so it doesn't hide a control from assistive tech.
- **RTL scoping** — confirmed correctly isolated per CLAUDE.md's public-page-language-isolation rule. `app/(public)/layout.tsx:57` hardcodes `dir="ltr"` for the page shell; only `app/(public)/w/[orgSlug]/layout.tsx:69-93` computes `effectiveDir` and passes it narrowly into `<ContactModal>` / `PortfolioHeader.tsx:338`. Tests assert this scoping (`layout.test.tsx:49`, `PortfolioHeader.test.tsx:434-436`). No hardcoded physical `pl-/pr-/ml-/mr-/left-/right-` classes found in the RTL-scoped components — logical properties used throughout.
- **Focus-visible** — `outline-none` is consistently paired with an explicit `focus-visible:ring-*` replacement (`components/ui/textarea.tsx:10`, `select.tsx:24,64,85`, `popover.tsx:27,38`, `dropdown-menu.tsx:36`, `tabs.tsx:41,53`, `color-picker.tsx:132,171`, `location-picker.tsx:471,490,501`, `NotificationPopover.tsx:61,126,136,169`, `lib/page-builder/toolbarPrimitives.tsx`, auth forms). No bare `outline-none` without a replacement found in the files sampled.

## Gaps
- **`components/ui/sidebar.tsx:183,201,228`** — the `Sidebar` root (used by the dashboard's primary nav via `components/app/app-sidebar.tsx:126`) renders a plain `<div data-slot="sidebar">`, never `<nav>` or `role="navigation"`. Menu items inside it are real `<button>`/`<a>` elements (:527,691), so it's operable — but assistive-tech users have no landmark to jump straight to the primary navigation.

## Fix direction
Add `role="navigation"` (or a `<nav>` wrapper) to the `Sidebar` root in `components/ui/sidebar.tsx`. This is the only real accessibility gap found in this pass — everything else sampled (forms, dialogs, drag alternatives, color-as-signal, alt text, custom widget ARIA, RTL scoping, focus-visible) is already handled correctly.

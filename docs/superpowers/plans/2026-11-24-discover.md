# Discover Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Discover feature: a marketing banner, the `/discover` masonry page and its modal, and an owner "List on Discover" toggle in Settings and the Publish dialog. Also reorder the marketing header.

**Architecture:**
- Listing state lives on `Workspace.discover`. `listed` has no schema default, and `listedAt` plus the fallback `cover*` fields are written only by explicit owner saves or publishes.
- Public reads are one cross-tenant aggregation with a strict projection whitelist. It filters on listed + published + not noindex + renderable + entitled (a query-side mirror of `isEntitled`).
- Nothing is cached:
  - `/discover` and its API routes are dynamic with `no-store`.
  - The marketing home is ISR (`revalidate = 60`), so the banner is a client island that fetches the live API.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind v4, Mongoose 8, Zod, next-intl (en/fil/id/ar/th), Vitest + in-memory Mongo, Playwright CLI.

**Spec:** `docs/superpowers/specs/discover-design.md` (staged on `design/discover-mockups`, not yet committed). Mockups are `docs/mockups/discover-marketing-section.html` (variant A) and `docs/mockups/discover-browse.html`.

**On approval:** copy this plan to `docs/superpowers/plans/2026-11-24-discover.md`. Work in worktree `.claude/worktrees/discover` on branch `action/discover`, created from `design/discover-mockups` after its staged spec is committed.

## Global Constraints
- **Spec wins:** where this plan and the spec disagree, follow the spec and flag it.
- **Tenancy:** Discover queries are the documented cross-tenant exception. Every per-workspace follow-up read, such as gallery items, includes `workspaceId`.
- **Projection whitelist:**
  - Allowed: `slug`, `name`, `businessType`, `country`, `discover.listedAt`, `discover.coverUrl|coverWidth|coverHeight`, `publicPage.seoDescription`, `publicPage.seo.ogImageUrl`, `publicPage.brandKit.{backgroundColor,foregroundColor,accentColor,headingFont}`.
  - Never: `contact.*`, `ownerUserId`, `inquiryRecipientEmail`, `publicPage.data`, or a `hideClient` client name.
- **Listed values:** `discover.listed` is `true`, `false` or unset. The query uses `"discover.listed": true` strictly. The UI default is `listed ?? true`. The confirm and warning compare against `savedListed = listed === true`.
- **`listedAt` rule:** set once, when it is null and the write leaves the workspace published AND `listed: true`. Never reset.
- **Confirmation:** applies only when the page is published (`publishedAt != null`) AND `toggle !== savedListed`. Never-published pages get no warning.
- **Design:**
  - Semantic tokens only, logical properties, flat surfaces.
  - The brand teal appears only on actions.
  - The warning uses the existing amber banner recipe in `settings/public-page/_form.tsx:313` (`border-amber-500/40 bg-amber-500/5 text-amber-700 dark:text-amber-400`).
- **i18n:** every UI task adds its keys to all 5 `messages/*.json` in the same commit. `messages/encoding-sanity.test.ts` stays green. Write JSON with UTF-8 edit tools, never PowerShell `Set-Content`.
- **Tests:** run with `pnpm test --run <fragment>` via the PowerShell tool, which tdd-guard needs. Never mock Mongoose; use `@/test-utils/mongo`. Components use `renderWithProviders` (`test-utils/render.tsx`).
- **Commits:** one per task, conventional style, with the `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` trailer.
- **Subagents:** never run `pnpm build`, the full typecheck or Playwright. Only the orchestrator runs these, one at a time.

## Review Focus
1. A search `q` containing regex metacharacters or over 60 chars must not throw or scan unbounded. It is escaped and capped, and the API returns 400 when over 60 (Task 4 and Task 5 tests).
2. A deep link `?p=<slug>` to an unlisted, gated or unknown portfolio renders the grid without the modal and without an error (Task 9 test).
3. A cover image URL that 404s (replaced or deleted asset) falls back to the brand tile in the browser, never a broken image (Task 8 test, simulated `onError`).
4. `country: null` or `businessType: "other"` produce no stray separator ("·") and no empty label (Task 8 and Task 9 tests).
5. RTL (`ar`): modal arrow keys are reversed, the banner mask and rotation flip, and the masonry overlay text aligns to the start (Task 9 and Task 10 tests, plus the Playwright run).

# Env Procurement Guide — WorkOS AuthKit + Turnstile

How to obtain every new environment variable required by the Clerk → WorkOS migration.
Fill the commented-out entries at the bottom of `.env.local` as you complete each section.

## 1. WorkOS account + application

1. Sign up at https://dashboard.workos.com/signup (free tier covers up to 1M MAU for AuthKit).
2. A default **Environment** (Staging) and application are created automatically. Use Staging for local dev; create/use Production later for deploys.

### `WORKOS_API_KEY`
- Dashboard → **API Keys** (left sidebar) → copy the **Secret Key** (`sk_test_...` in Staging).
- Server-only. Never expose with `NEXT_PUBLIC_`.

### `WORKOS_CLIENT_ID`
- Same **API Keys** page → copy the **Client ID** (`client_...`).

### `NEXT_PUBLIC_WORKOS_REDIRECT_URI`
- Dashboard → **Redirects** → add `http://localhost:3000/api/auth/callback` and set it as default.
- Put the same value in `.env.local`. For production, add the production URL (`https://<domain>/api/auth/callback`) as a second redirect in the dashboard.

### `WORKOS_COOKIE_PASSWORD`
- Not from the dashboard — you generate it. Must be **at least 32 characters**; it encrypts the sealed `wos-session` cookie.
- Generate locally:
  ```bash
  openssl rand -base64 32
  ```
  (or in PowerShell: `[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))`)

### `ACTIVE_WORKSPACE_COOKIE_SECRET`
- Also generated by you, same method as above (`openssl rand -base64 32`). Signs the `gw_active_ws` active-workspace cookie. Use a **different** value than `WORKOS_COOKIE_PASSWORD`.

## 2. WorkOS authentication settings

In Dashboard → **Authentication**:

1. **Email + Password**: enabled by default — leave on.
2. **Google OAuth (social login)**:
   - Authentication → **Social login** → enable **Google**.
   - For dev, WorkOS's shared Google credentials work out of the box. For production you must supply your own Google OAuth client (Google Cloud Console → APIs & Services → Credentials → OAuth client ID → authorized redirect URI shown on the WorkOS Google config page).
3. **MFA (TOTP)**: Authentication → enable **Two-factor auth**. No env var needed.
4. **Email verification**: leave **required** (the invite-accept flow asserts verified email).
5. **Webhooks**: leave **disabled** — JIT provisioning is the primary sync path at cutover. If you enable later, Dashboard → Webhooks → create endpoint → copy signing secret into `WORKOS_WEBHOOK_SECRET`.

## 3. Cloudflare Turnstile

1. Sign in at https://dash.cloudflare.com (free account is enough; Turnstile is free).
2. Sidebar → **Turnstile** → **Add widget**.
3. Widget settings:
   - Hostnames: `localhost` plus your production domain.
   - Widget mode: **Managed** (recommended).
4. After creation, copy:
   - **Site Key** → `NEXT_PUBLIC_TURNSTILE_SITE_KEY` (public, used by the client widget)
   - **Secret Key** → `TURNSTILE_SECRET_KEY` (server-only, used to verify tokens)

> Dev shortcut: Cloudflare publishes always-pass test keys — site key `1x00000000000000000000AA`, secret `1x0000000000000000000000000000000AA` — useful before you create the real widget.
